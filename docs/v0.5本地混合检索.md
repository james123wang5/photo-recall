# PhotoRecall v0.5：全本地混合检索

## 已接入的流程

导入/更新照片文件 → 复用并补全WeMM与SigLIP整图、局部向量 → PP-OCRv6提取文字及位置 → Qwen3.5-4B生成一次结构化画面描述 → Qwen3-Embedding-0.6B编码描述 → 图像、描述语义、关键词和OCR分组融合 → 复杂查询最多核对4张原图（可配置上限8张），无需默认精排64张。

已有照片库点击网页顶部「增强检索」启动新信息的建立。可以暂停、继续；图像向量不会重做。新文件夹的普通索引完成后会继续增强。初次增强可能需要数小时，画面理解耗时较多；这与查询的等待时间不同。描述过程中每32张发布一批文字向量，不用等全部结束才可利用。

所有推理在本机完成。没有调用付费API、上传照片或训练模型。模型下载走网络；运行时接口仅连接127.0.0.1。

## 模型与OCR选择

- WeMM-Embedding-2B、SigLIP2：原有视觉索引保留。
- qwen3.5:4b：Ollama中的本地量化视觉语言模型，用于离线观察。现有qwen3-vl:4b-instruct保留为逐项核对模型。
- qwen3-embedding:0.6b：独立1024维中英文文本空间；不与图像向量直接点积。
- PaddleOCR 3.7.0、PaddlePaddle 3.2.1、PP-OCRv6_medium_det/rec：CPU独立进程复用，原有模型复制到本项目data/models/paddleocr，未改动SnapNote项目。独立环境.venv-ocr，版本记录requirements-ocr.lock.txt。
- Apple Vision：Swift本地辅助程序备用，Paddle运行失败时回退并记录原因。未启用PaddleOCR-VL文档解析、表格、公式管线。

两种OCR在一张合成中英文图片上都读出了主要内容。该检查仅证明接口可运行，不是照片OCR准确率排名，不能证明Paddle普遍优于Apple。选择Paddle作为本版主后端，是因为用户已有PP-OCR模型、已在本机跑通，并且方便后续调节图像处理。

## 检索与证据边界

FTS5使用显式中文双字切分和英文词项，不依赖默认空格分词。图像同家族的整图、局部与改写检索只取该家族最佳名次贡献，描述关键词/向量也不算两份独立证据；家族之间用RRF合并。描述覆盖不全时按覆盖比例降低描述家族贡献，保留未生成描述的照片进入图像搜索。

OCR原文、画面描述、模型版本、照片指纹、OCR框分别保存。描述缺少某对象不代表对象不存在；模型文字不能作为强制过滤条件。每轮都从全库索引检索。

普通查询不跑CORE；复杂查询本地逐图一次核对所有条件，保留未知。最多提升4张有支持证据的照片，其他维持原顺序；一次低分不把照片全部后移。前端支持「原始检索顺序」回退。CORE保留在高级工具手动扩大精排中。

在线搜索优先于离线建库：后台在图片/小批次间让出资源。已经开始的单次模型推理不能立即抢断。大模型互斥加载；OCR在独立CPU进程，任务暂停/完成后退出。

## 数据、恢复与检查

新增observations、observation_fts和hybrid_query_vectors表，未删除原索引。文件变化、模型/提示版本变化后增量失效。可恢复备份在data/backups/local-hybrid-20261015。

已完成代码逻辑检查（42项）及合成图片OCR、单张结构化描述、文本向量接口检查。没有进行整库准确率评测，没有达到95%的证据，也没有把建库耗时当作查询耗时。性能与准确率仍需日常使用记录。

API：POST /api/libraries/{id}/hybrid-index；GET /api/libraries/{id}/job；POST /api/libraries/{id}/pause。GET /api/models显示OCR与模型准备状态。POST /api/settings可设置hybrid_search、hybrid_auto_verify。关闭hybrid_search可恢复原CORE链路。
