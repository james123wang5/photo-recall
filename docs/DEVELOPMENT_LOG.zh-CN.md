# PhotoRecall · 本地照片搜索

## v0.6：完整搜索链路 Demo（2026-10-27）

默认首页现为新版完整链路；旧版仍可通过 `/legacy` 打开。下面的 v0.4 说明保留作历史参考。

新版链路：**文件扫描 → 分层建库 → 原文与条件 → 多路召回 → 保留候选 → 按需精排／原图与局部核验 → 有限扩大搜索 → 用户反馈**。集合任务另有固定范围快照、逐张进度、暂停与继续。

本次只开发和静态检查，没有启动应用、运行照片、模型推理、自动化测试或准确率／性能测评。运行效果和环境兼容性待用户自行检查。

启动方式仍为双击项目中的「启动.command」。若旧服务仍在运行，先用「停止.command」停止，再启动新版。默认地址为 `http://127.0.0.1:8765`。

首次使用：

1. 选择或添加真实照片文件夹，点击「更新文件」；这一步只扫描文件并生成缩略图。
2. 点击「建立搜索索引」，选择图像与局部、文字、描述等需要的步骤。已有有效结果复用，可暂停后再次点击相同步骤继续。
3. 输入线索，选择「找那一张」「找相关的一组」或「尽量找齐全部」。默认保留全部相关候选。
4. 可撤回线索、点击「这批还没找到，继续找」，或打开照片选择「不是这张」「参考这张继续找」。在原图上拖动可指定参考局部。
5. 「尽量找齐全部」按当前范围逐批处理；达到时间预算后点「继续处理」。处理失败与无法判断分别记录。

默认复用已有 WeMM／CORE／SigLIP／本机视觉模型。Qwen 多模态召回与精排、开放对象定位、人物分组均有适配入口，需准备对应本地依赖和权重；缺失时显示状态，不自动下载或上传照片。

完整开发说明、模块关系、接口、模型路径和边界见 [v0.6 完整链路开发说明](v0.6完整链路开发说明-2026-10-27.md)。

修改前的代码副本保存在 `data/backups/flow-development-20261027/`。新链路使用独立的 `flow_*` 表，不删除原索引和原照片。

## 历史 v0.4 说明

v0.4，面向 M1 Pro / 16GB Mac。

当前项目位置：`/Volumes/Lexar/桌面项目归档/PhotoRecall`。双击这里的「启动.command」运行，移动硬盘需要保持连接。启动器会自动适配项目移动后的运行环境。

网页与图库沿用原版，检索后端升级为：

**全库整图与局部召回 → 候选合并 → CORE 多条件精排 → 按需核对少量原图。**

模型和照片推理均在本机。新版不是已通过 95% 准确率验收的产品；实际回归结果见 `docs/v0.4本机实现与实测.md`。

## 使用

双击 **启动.command**，浏览器打开 http://127.0.0.1:8765 。双击 **停止.command** 停止。启动窗口需要保持打开。

1. 选择已有照片库，或点「添加本地文件夹」。支持 JPEG、PNG、WebP、BMP、TIFF 和子目录。
2. 已有照片点「建立新版索引」；新文件夹点「更新索引」，先扫描文件再建立新版视觉索引。只处理新增或改变的内容，可暂停、续建。
3. 输入完整描述。先显示候选，后台精排陆续更新顺序；补充、纠正或移除线索时，重新检索整个图库。
4. 尚未找到时点「扩大精排范围」，从默认 64 张扩到 128、256 张。范围越大等待越久。
5. 手势、车标、人数等需进一步确认时，点「核对候选细节」，每批 3、6 或 12 张；也可点开照片，单独核对这张。原图和检测结果配合核对。

默认保留未核对、未知和条件冲突的候选；冲突结果降序显示。可勾选「只看逐项核对较符合的照片」。相关性分数不代表匹配概率，也不代表条件已经全部核对。

界面中的「记忆练习册」是预设插画演示，不代表模型效果。

## 本地模型

- `data/models/wemm-2b`：腾讯 WeMM-Embedding-2B，2048 维主索引。
- `data/models/core-reranker-2b`：阿里 CORE-Reranker-2B，多条件相关性精排。
- `data/models/siglip2`：沿用 SigLIP 2 整图补漏，新建四个重叠局部向量。
- `data/models/yolo26n.pt`：已有目标检测缓存，提供位置与数量下限。
- Ollama：`qwen3:4b` 解析对话，`qwen3-vl:4b-instruct` 按需核对原图。

两个新模型共约 9.7GB 权重，与项目一同位于 Lexar 上的 `data/models`。固定下载版本记录在各目录的 `photorecall-source.json`。服务器只读取完整本地文件，不会隐式联网下载模型。重新安装：

```sh
.venv/bin/python -m pip install -r requirements-ai.txt
.venv/bin/python scripts/prepare_ai.py --download
.venv/bin/python scripts/prepare_retrieval.py --download
.venv/bin/python scripts/prepare_detector.py --download
```

Mac 使用 PyTorch MPS（苹果 GPU），不要求 CUDA。模型按阶段互斥加载，避免几个大模型同时常驻；对话调用完成后卸载 Ollama 模型。保留 Ollama 服务，不卸载用户模型文件。

## 数据与恢复

原照片保留在原文件夹，不改写。SQLite 中独立保存模型版本、指纹、整图／局部向量、精排缓存和搜索阶段记录。旧 SigLIP 索引仍保留。

改造前代码、网页与数据库备份：`data/backups/v0.3`。新索引无需覆盖旧索引。设备断开、原片变化和索引缺失会影响检索，界面显示索引完成数量与错误。

## 验证和边界

```sh
.venv/bin/python -m unittest discover -s tests
PYTORCH_ENABLE_MPS_FALLBACK=1 .venv/bin/python scripts/benchmark_retrieval.py
```

前者验证流程、缓存、取消、索引版本和文件安全；后者只检查已知生日与汽车案例，不是独立泛化测试。日志和结果保存在 `data`。

精确人数、遮挡、否定、左右关系、小手势仍可能出错。检测数量是下限，不是完整人数证明。只有图片标签、描述或单个向量，都不能保证保留所有细节。

当前仅绑定本机地址。不包括手机接入、HEIC／RAW／视频／Live Photos，也没有在一万张规模上实测。手机端另行研究。
