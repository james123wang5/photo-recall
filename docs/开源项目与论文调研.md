# 细粒度、多条件、多轮照片检索调研 · 2026-10-13

本次只查公开原始资料与规划，不下载新模型、不继续运行私人照片逐图验证。公开页面优先由 Lightpanda 抽取；arXiv HTML 被拦截时用内置网页工具回退。以下能力是作者公开描述，不等于已在本机验证。

## 与需求最直接相关的项目

| 项目 / 单位 | 能借鉴什么 | 对 PhotoRecall 的决策 |
|---|---|---|
| [ImageScope · USTC / Baidu，WWW 2025](https://github.com/pengfei-luo/ImageScope) | 已有完整语言引导检索框架，分阶段组织意图、检索、验证和候选比较 | 最接近可参照的流程。原版依赖 CUDA / vLLM，模型组合含 7B、8B 和 3B，且缓存描述参与检索；不原样装到 16GB Mac，不把描述当唯一证据 |
| [CORE · Alibaba 等，2026](https://github.com/Alibaba-NLP/core-emb) | 针对属性与对象绑定、组合关系训练检索和精排；包含评估代码 | 优先比较 core-reranker-2b，与 Qwen 原精排作对照；core-emb-2b 作为后续检索候选 |
| [Qwen3-VL-Embedding / Reranker](https://github.com/QwenLM/Qwen3-VL-Embedding) | 专业多模态召回与图文精排，支持中文等多语言 | Qwen3-VL-Embedding-2B 是首版可复现的检索候选，不默认把通用聊天输出当排名分数 |
| [Grounding DINO · IDEA Research](https://github.com/IDEA-Research/GroundingDINO) | 通过文本提示定位对象，返回框 | 对少量候选按当前问题定位人、车、树；输出对象位置，不把检测本身当作关系推理的完成 |
| [Grounded SAM 2](https://github.com/IDEA-Research/Grounded-SAM-2) | 已组合开放词汇检测与分割 | 在颜色 / 外观问题需要时提取对象掩膜，减少蓝天背景误算成蓝车的情况；不默认给每张照片跑全部分割 |
| [Florence-2 · Microsoft](https://huggingface.co/microsoft/Florence-2-base) | 小型统一视觉任务模型，支持区域与定位相关任务 | 作为较轻的区域工具备选；不是核心向量检索器，其本机定位质量待确认 |
| [FiftyOne · Voxel51](https://docs.voxel51.com/user_guide/similarity.html) | 已支持图片、对象区域的相似索引、自然语言搜索与可视检查 | 可复用为开发 / 标注 / 误差分析平台，现有用户网页保留；SDK 本身不解决复杂关系与错误记忆 |
| [Immich](https://docs.immich.app/features/searching/) | 成熟照片导入、向量搜索和元数据筛选 | 参考索引生命周期和图库管理，不把普通 smart search 当成关系理解完整解法 |
| [ColPali / ColQwen · ILLUIN](https://github.com/illuin-tech/colpali) | 每个图像保存多个局部向量，用后期交互匹配细节 | 借鉴多向量思想；主要训练和测试于文档页面，不能照搬其分数到自然照片。当前项目建议新应用用 Sentence Transformers 的多向量接口 |
| [Dialog-based Interactive Image Retrieval](https://github.com/XiaoxiaoGuo/fashion-retrieval) | 利用自然语言反馈逐轮改善目标排名 | 交互机制参考，原实现以服饰数据与旧软件栈为主，不是通用相册成品 |
| [PicHunter](https://www.researchwithrutgers.org/en/publications/the-bayesian-image-retrieval-system-pichunter-theory-implementati/) | 用历史相关反馈更新目标候选的概率式搜索 | 借鉴保留候选和反馈更新思想；并不代表已有现成模块能自动纠正任何错误记忆 |

## 专门说明问题的论文

- [SugarCrepe](https://github.com/RAIVNLab/sugar-crepe)：评估只改属性、对象或关系的困难负例；发现强模型仍难以正确组合这些信息。
- [NegBench](https://github.com/m1k2zoo/negbench)：专门检验否定条件，表明“有某物”和“不含某物”不能简单依赖普通相似度。
- [ComCLIP](https://github.com/UCSB-AI/ComCLIP)：实体 / 局部与组合匹配的研究参考；原代码含密集描述与外部 API 依赖，不作为本地首版的直接安装路线。
- [CORE 原文](https://arxiv.org/html/2609.04083v1)：论文表 1 的组合基准总平均中，Core-Reranker-2B 为 0.776，Qwen3VL-Reranker-2B 为 0.676。该指标来自 COLA、SugarCrepe++、NegBench，不是私人一万张照片的成功率。论文中的 94% 是小批合成训练样本的人审通过率，不是检索准确率，不可混用。

## 权重与硬件核查

- [core-reranker-2b 官方文件](https://huggingface.co/Alibaba-NLP/core-reranker-2b/tree/main)：有完整 safetensors 权重，约 4.26GB；本次元数据 revision 为 64e1a36cd6ecace459a4c7cd8f7d0ef5d6fee30b。
- [core-emb-2b 官方文件](https://huggingface.co/Alibaba-NLP/core-emb-2b/tree/main)：有两片 PyTorch bin 权重，合计约 8.51GB；本次 revision 为 cc9870ea92d64ebd5f8f9fc368d1120453564158。文件大不意味着必定有更多参数；加载精度和峰值内存需要单独处理，不盲目同时加载。
- Qwen3-VL-Embedding-2B 与原 Reranker-2B 官方 safetensors 各约 4.26GB。运行还需要激活、图像 token、缓存与系统内存。Mac 适配须核对官方处理器、池化 / 评分方法与精度，不能只换模型名字。
- [SAM 3](https://github.com/facebookresearch/sam3) 已支持文本概念检测分割，但官方安装路线要求 CUDA GPU；本机首版不以它为默认依赖。
- [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2) 可作为相对深度提示。相对深度不能独自证明人的位置在车头前，也不能从无尺度单张照片可靠给出树的米制高度。

## 调研结论

本次找到可参照的完整研究流程、检索 / 精排权重和成熟对象工具，未找到已公开证明在 M1 Pro 16GB 上，对任意一万张自然照片、多条件、多轮且有错误记忆的任务同时达到 95% 与低延迟的现成成品。建议采用可复用组件组成有边界的链路，并以独立任务验证；当前不训练新模型。
