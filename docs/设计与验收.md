# 第一版设计与后续验收

## 目标

用模糊的中英文描述查找普通文件夹中的照片。允许用户逐轮追加和纠正条件；索引可复用，新增图片增量处理。先在 M1 Pro / 16GB Mac 验证，再决定手机或 Windows 产品化。

## 数据流

选定文件夹 → 文件清单 → 缩略图 / 元数据 → 可选视觉特征 → 持久化。

用户描述 → 保存条件 → 全库候选检索 → 快速结果 → 按需看图核对 → 重新排序。

演示模式：预设插画标签检索，用来验证界面和状态流程。
文件信息模式：仅搜索文件名、路径、可靠拍摄日期。
画面模式：安装模型后由 SigLIP 2 编码图片与文字，比较视觉特征。

## API 工具

| 操作 | API |
|---|---|
| 照片库与运行状态 | GET /api/state |
| 添加目录 | POST /api/libraries |
| 选择 Mac 文件夹 | POST /api/pick-folder |
| 建立 / 继续索引 | POST /api/libraries/{id}/index |
| 进度 / 暂停 | GET /api/libraries/{id}/job；POST /api/libraries/{id}/pause |
| 检索与条件变更 | POST /api/search |
| 看图核对 | POST /api/inspect |
| 预览 / 原图 / 定位 | /api/assets/{id}/thumbnail；original；reveal |
| 模型状态 / 画面开关 | GET /api/models；POST /api/settings |

所有可修改状态的请求需要当前页面 token。本地接口通过照片记录定位文件，不接受任意文件读取路径。目录以用户明确添加为准，不跟随符号链接，原图只读。

## 原型验收（本次）

- 网页可以启动，演示库搜索「树 → 车 → 可能白色」结果逐步变化。
- 可能条件影响排序，而不是把所有其他颜色排除。
- 移除条件后结果扩大；新搜索不会保留旧条件。
- 添加测试目录后出现缩略图、元数据与索引进度。
- 再次索引没有改动的图片只复用；新增图片单独处理。
- 原图内容不变；坏图显式报告；源目录暂时不可访问时保留旧索引。
- 演示 / 文件信息 / 画面模式均明确说明，不用预设标签假装 AI 看图。
- 未准备 AI 模型时能继续浏览，模型相关操作解释缺失条件。

## 真实照片阶段验收（待执行）

留出约 60 个任务，调试与验收任务分开：20 个常见场景，20 个组合与空间关系，20 个多轮回忆。每个任务事先确认目标或可接受结果，中英文分别统计。

| 指标 | 建议目标（尚未验证） |
|---|---|
| 常见场景 | 90% 任务在前 20 张找到目标 |
| 组合关系 | 75% 任务在前 20 张找到目标 |
| 多轮任务 | 80% 任务在三轮内进入前 20 张 |
| 热启动普通搜索 | 一万张固定测试库，95% 首屏 ≤5 秒 |
| 看图核对 | 先测 8 张；再评估 20 张 / 60 秒的可达性 |
| 原文件完整性 | 修改数量为零 |
| 离线 | 模型准备好后，断网可索引、检索、核对 |

分别统计「目标进入前 100 候选」与「目标进入前 20」，以区分检索失败和排序失败。样本量小的结果报告任务数和失败案例，不泛化为所有照片的准确率。

## 后续优先级

1. 安装 SigLIP 2，先测 200～500 张真实照片的索引吞吐、内存、MPS 与中英文搜索。
2. 比较基础检索与 Qwen3-VL-Embedding-2B；替换模型后重建视觉索引。
3. 接入大模型结构化意图解析，保留原描述和确定 / 偏好 / 排除条件；显式校验。
4. 验证 Qwen3-VL 看图核对，与专用 Reranker 比较排序质量、等待时间和内存。
5. 优化向量缓存、分块检索 / Faiss、对话取消和任务队列。
6. 根据真实使用反馈补充 OCR、人脸命名、HEIC、局域网手机入口。

当前不训练或微调。只有持续出现明确领域失败，且已有独立评测与标注数据时，才考虑微调。
