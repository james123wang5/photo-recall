# 检索架构重新评估 · 2026-10-13

后续详细规划已加入：[多条件多轮照片检索方案](多条件多轮照片检索方案.md)与[开源项目及论文调研](开源项目与论文调研.md)。新调研增加 CORE 2B 精排候选、对象绑定和错误记忆分支；此前模型选择视为基线建议。

## 结论

暂停逐张补错式改进，保留现有网页、原图、数据库和基础索引作为对照。下一阶段重做检索核心：导入时建立可复用的信息，搜索时采用专业检索与相关性评分，把生成式看图解释降为少量困难候选的辅助工具。当前实验结果不能当成整体准确率认证。

## 公开工业方案的依据

Google Research 明确披露 Ask Photos 使用向量检索结合元数据，再由 Gemini 分析召回结果；苹果公开多个结合特征向量、标签、人物与关联信息的模块。相关事实与适用边界见 [苹果与谷歌照片检索思路](苹果与谷歌照片检索思路.md)。新方案参考这些公开分工，标签与描述仅作辅助，不要求用标签穷举所有可搜索的画面。

## 现有链路为什么不适合目标

1. 224 输入的全图向量主要压缩整体语义，小手势、遮挡人物与复杂关系可能丢失。查询拆分与手工加权不能恢复已经丢失的图像信息。
2. 通用 Qwen3-VL 4B 擅长生成描述，但描述遗漏和模型猜测会直接传到排名。一次要生成大量文字，再逐张核对，代价高；数量下限、模型计数和最终解释也可能冲突。
3. 人数、光影、构图、场景不能只靠同一种相似度。全库相对分数也不是概率，任意固定加权缺乏独立标注依据。
4. 主要结果只展示核对过的照片可以降低部分错误，却可能隐藏大量待核对图片。应同时衡量命中、覆盖、明显矛盾率和等待时间，不能只看留下的一两张。
5. 已接入的详细画面索引在用户的 338 张图库中尚未完成；目前大部分昂贵判断仍发生在每次提问时，没有实现用户期望的一次准备、多次快速查询。

## 拟采用的流程

### 导入阶段：成本放在一次准备中

- 基础图像与元数据，保存稳定资源 ID、内容指纹、拍摄日期；保留原图。
- 专业多模态模型编码全图；针对人物等主体保存有限数量区域特征。全图用于光影、构图和场景，局部用于人物外观、动作和小物件；区域位置必须随特征保留。
- 目标检测、OCR 和有限的结构化描述按内容指纹缓存。数量保存下限、疑似目标与不确定性，不把未检出视为零，不把一个主体误写成全图只有一人。
- 重要事实区分主体与背景、出现与相邻、单人主体与全画面单人。模型给不出证据时存未知，不能补齐成确定事实。

### 查询阶段：有预算的检索与排序

1. 保留原始中文与完整会话要求；明确数量、排除和日期由可检查的约束表示。大语言模型可辅助理解，但不能删改原始线索或决定照片是否符合。
2. 图文向量、区域特征、文字描述与元数据多路召回，合并去重。先检查已缓存的明确矛盾，不在每次查询重新扫描全库图片。
3. 仅对合并后的前 20 至 30 个候选进行专业图文相关性重排，直接评估原始问题与图片 / 描述的匹配，不生成长篇解释。候选量与分辨率受时间和内存预算约束。
4. 少量仍有争议的候选才调用生成式看图模型；默认搜索与深入核对分开。明确矛盾退出结果，未知需有可见标记，不能以低覆盖率冒充高准确率。

不同查询仍可能需要重新计算小批候选的图文匹配；一次索引不能无损保存照片里的所有潜在细节。目标是避免每次重复分析整库，而非承诺以后所有问题完全无需看图。

## 模型候选与证据

| 用途 | 候选 | 决策 |
|---|---|---|
| 对照组 | 已安装 SigLIP 2 base 224 | 保留，便于知道升级是否真正改善 |
| 检索核心候选 | Qwen3-VL-Embedding-2B | 专门训练用于多模态检索，官方支持中文等多语言；优先做候选比较，尚未接入 |
| 图文精排候选 | Qwen3-VL-Reranker-2B | 专门评估查询与图文内容相关性；应与“不重排”直接比较，不默认开启 |
| 轻量路线备选 | 更高分辨率 SigLIP 2 + 已缓存结构化事实 | 当 Qwen 路线不满足本机速度 / 内存时再评估；不同时盲目安装多个模型 |
| 困难细节辅助 | 通用视觉语言模型 | 用于导入时描述或少量候选核对，停止把逐图长解释作为主排序器 |

官方资料中的图像检索指标并不证明加上 2B 重排一定更好：截至本次抓取，Qwen GitHub 表中 Embedding-2B 图像检索为 74.8，Reranker-2B 为 74.0。模型卡与 GitHub 指标存在版本差异，因此不跨版本拼接排行，更不把公开基准等同于私人照片库效果。

官方 2B Embedding 和 Reranker 权重各约 4.26GB，下载大小不是峰值运行内存。16GB Mac 不应默认同时常驻多种大模型；候选方案优先考察 MLX、量化、分阶段加载、候选小批处理和中间特征缓存。MLX-VLM 项目已列出相关多模态 embedding / rerank 支持，但本机兼容性、量化输出一致性与速度尚未验证。8B 不作为默认起点。此时不下载新大权重、不重跑全库、不训练新模型。

## 一次固定比较，代替不断追着个例改

先固定约 100 张代表性照片及 30 条问题，覆盖物体 / 人物、数量与排除、动作、光影、构图、视角六个维度；相似连拍与同名不同图须明确区分。人工标签区分符合 / 不符 / 未知，不编造找不到的目标。问题预先划分开发集与保留集，改规则时不能查看保留集答案。

对同一批问题比较三组：现有基线、专业 embedding、多路召回加专业 reranker。导入只做一次，后续问题复用索引与中间结果；先在固定集合比较，达到门槛后才扩展全库。无需用户不断找新的失败照片。

记录目标是否进入前 50（召回）、前 5 是否找到目标（首屏体验）、明显条件矛盾率、未知 / 空结果率、索引时间、查询 P50 / P95 与峰值内存。无候选集目标时，重排无法补救；有候选却排错时，才重点改精排。功能测试与模型准确率分开记录。

建议原型门槛（目标，尚未测得）：至少 80% 的有目标任务在前 5 出现；明确数量 / 排除矛盾任务率不超过 5%；初筛 P95 不超过 2 秒、最终默认结果 P95 不超过 10 秒。不允许通过把大部分任务都显示为空来达到矛盾率目标。门槛未达时依据失败层决定是否换模型，不继续无限加后置核对。
